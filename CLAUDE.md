# Study Arc (Y4S1 study hub): project guide

A static website (GitHub Pages) of study notes for one student's USM Year 4 Semester 1 subjects.
Repo `vonAkym/vonAkym.github.io`, served at `https://vonakym.github.io/`. Plain HTML, CSS and a little JavaScript. No framework, no build server.

## Layout

| Path | What it is |
|---|---|
| `index.html` | Hub home page (subject menu). Generated by `tools/build_hub.py`. |
| `cmt322/index.html`, `cmt322/img/` | CMT322 Web Engineering notes (Weeks 1 to 5). Generated by `tools/build_notes.py`. |
| `cst435/index.html` | CST435 Parallel and Cloud Computing notes (Topics 1 to 5). Generated by `tools/build_cst435.py`. |
| `cmt323/index.html` | CMT323 notes (Weeks 1 to 3, textbook Chapters 1 to 3). Generated by `tools/build_cmt323.py`. |

| `tools/` | The generators and shared CSS/JS. See `tools/README.md`. |

**Never hand-edit the generated `index.html` files.** Change the script in `tools/`, rerun it, commit both.

## Build

```
python3 tools/build_hub.py
python3 tools/build_notes.py
python3 tools/build_cst435.py
python3 tools/build_cmt323.py
```

Each writes into the repo root. Run all four after changing shared files in `tools/` (`style.css`, `extra_cst.css`, `bigp.css`, `script.js`, `notes_lib.py`).

## How every subject page is taught

The owner learns by connected storyline, not by memorising separate facts. Every topic or week is told as **problem, then solution, then the new problem the solution creates**, and that new problem is the next topic's starting problem.

Each notes page has, in this order:
1. **Big picture** at the very top: one guiding question, the chain of topics with a "but then" gap between each, how the first topic connects to the last, a grid of threads that run through all topics, five summary sentences.
2. **Previously on...** story cards.
3. One section per topic: problem/solution/new problem strip, mind map, visuals, terms to know, "Boss fight" questions with reveal-on-tap model answers.
4. Cheat sheet (numbers, formulas, exam traps) and flashcards.

## Content rules

- Use only what is in the owner's lecture files. Anything that is your own summary, calculation or link between topics must be labelled as such on the page (see the "my own summary" notes). If the slides leave something blank or give no answer, say so; do not invent it.
- Redraw diagrams. Do not copy figures from textbooks or other publishers. CMT322 does include cropped lecturer slides (the owner chose that); do not add more slide images without asking.
- Check every number and formula against the slides before writing it down.
- Quiz questions need model answers. Calculations show their working.
- Keep wording plain. Explain a technical term the first time it appears.

## Design rules

- **Hub**: dark cosmic style (Unbounded + Figtree, violet accent, glossy orbs). Everything is in `tools/build_hub.py`.
- **Notes pages**: graph-paper notebook style (Bricolage Grotesque + IBM Plex). Topic accent colours are the classes `w1` to `w5`. Shared styles live in `tools/style.css`, CST435-only components in `tools/extra_cst.css`, the Big picture block in `tools/bigp.css`.
- Mind maps are inline SVG built by `mindmap()` (`tools/notes_lib.py` for CST435; `build_notes.py` has its own copy). Keep leaf labels under about 34 characters.
- Accessibility and motion (from the animation audit): animate only `transform` and `opacity`; gate hover effects with `@media (hover: hover) and (pointer: fine)`; honour `prefers-reduced-motion`; keep the hub's pause-animations button; 44px minimum touch targets; visible keyboard focus; text contrast at least 4.5:1; nothing may scroll sideways at 375px (wide tables and mind maps scroll inside their own box).

## Before every push

1. Rebuild all four pages.
2. Open each page in a headless browser: no console errors, no horizontal scroll at 375, 768 and 1280px, hub links to `cmt322/#week-N` and `cst435/#week-N` and `cmt323/#week-N` resolve.
3. Commit with a clear message and push to `main`.
4. Confirm with `git ls-remote origin main` that GitHub's commit equals the local one. A push that "seemed to work" has failed before.
5. GitHub Pages can take a minute or two to update. The browser may need a hard refresh.

Ask the owner first before: deleting files, changing the hub's look, adding images from lecture slides, or anything that exposes more of their material publicly (the repo and site are public).

## Adding a new subject

1. Get the lecture files from the owner's computer (`Desktop/File/USM/Y4S1/<code>/...` on their machine; they are not in this repo). Read all of them; some decks are image-heavy and need rendering.
2. Work out the storyline between topics first. Write the five Big picture sentences before building anything.
3. Copy `tools/build_cst435.py` as the starting point (it uses the shared helpers). Put the subject's own data (mind maps, visuals, terms, questions, flashcards) in the new script.
4. In `tools/build_hub.py`: flip the subject card to `ready=True` with `href='<code>/'`, add a topic list section, and update the counters (ready count and total flashcards).
5. Run the checks above and push.
