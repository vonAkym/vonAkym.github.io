The road to multi-core

  1. Vacuum tubesEarly machines, huge and slow.
  2. TransistorsSmaller, cheaper, more reliable.
  3. Integrated circuitA CPU on one chip: the microprocessor (8080 up to Pentium 4).
  4. Clock wallHigher frequency means more heat and power, so single-core speed stalls.
  5. Multi-coreUse extra transistors for more cores instead (CMP).

Moore's law (as the slides state it): transistor density doubles roughly every 18 months. More transistors kept arriving, but they could no longer be spent on a faster clock.

Parallel vs distributed

Parallel systemDistributed system
GoalFaster execution of one applicationSharing resources, higher throughput
Grain sizeFineCoarse
ArchitectureTightly coupled, homogeneous, may share memoryLoosely coupled, heterogeneous, no shared memory

They overlap: both use many processors on a network, with several activities running and cooperating at once. Shared research issues: interprocess communication, resource management, scheduling and load balancing, grain size.

Worked example: summing 1024 numbers

PE#0 holds the whole array and splits it by sending halves to other PEs. Serial time is 1023 additions. Each addition costs 1 time unit and each send costs 3. Notice that speedup rises with p, but efficiency falls because communication grows.

p = 2speedup 1.975 · eff. 98.75%
p = 4speedup 3.803 · eff. 95.07%
p = 8speedup 6.91 · eff. 86%

Bar length = efficiency (speedup divided by p). The dark line is ideal linear speedup. Runtimes were 518, 269 and 148 time units.

Strong vs weak scalability

Strong scalability

Vary the number of processors, keep the input size fixed (the slides use n = 1024 and p from 1 to 512).

Weak scalability

Vary the number of processors and grow the input with them (n = 1024 × p).

Parallelism basics

Distributed memory

Each process has its own memory. Cooperate by point-to-point or collective messages over an interconnection network (example: MPI). Partition the data across processes. PGAS mixes this with a global address space.

Shared memory

Cores share one main memory over a bus or crossbar, as in multi-core CPUs. Risks: race conditions and keeping caches coherent (cache-coherent NUMA). Examples: Pthreads, OpenMP, CUDA.

Designing a parallel program means deciding: how to partition (data, task or model parallelism), how to communicate, how to synchronise, and how to balance load.

Terms to know

Moore's law
Transistor density doubles roughly every 18 months (as the slides state it).
Multi-core / CMP
Several processor cores replicated on a single die and socket. Also called Chip Multi-Processor.
Hyper-Threading
Two threads execute at the same time on one core, so the OS sees two logical processors.
Parallel computing
Using multiple processors together to solve a problem faster than one processor could.
Examples of parallel machines
A cluster of PCs on a fast network, a shared-memory multiprocessor (SMP), and a chip multi-processor (CMP).
Distributed system
Autonomous computers interconnected so they cooperate and share resources. Examples: cluster, grid.

Cost
Run time T(p) multiplied by p.
Computation-to-communication ratio
Time spent computing divided by time spent sending messages. Higher means better speedup and efficiency.
Strong / weak scalability

1Why did the industry move to multi-core instead of just making one core faster?

Clock frequency was getting hard to raise: deeply pipelined circuits run hot, the power draw and cooling costs grow, and designing and verifying such chips needs huge teams. Meanwhile more transistors kept arriving, so the spare transistors went into more cores. Doubling the cores while halving the frequency keeps the same performance at about a quarter of the power. Many applications were also already multithreaded.

2In the summation example (n = 1024) the serial time is 1023 and the 8-PE run takes 148. Find the speedup and efficiency, and say why efficiency is lower than with 2 PEs.
  • Speedup = 1023 / 148 ≈ 6.91.
  • Efficiency = 6.91 / 8 ≈ 86% (with 2 PEs it was 98.75%).
  • Why: more PEs means more distribution steps, each costing communication time (3 units per send), so a larger share of the run is communication instead of useful addition. The computation-to-communication ratio drops.
3Quiz from the slides: machine A does 10 jobs/hour at $100/hour, machine B does 2 jobs/hour at $15/hour, and finishing earlier saves $6 per hour. You have 10 jobs. Which machine?

My working (the slide gives no answer, so treat this as my reading):

  • A: 10 jobs take 1 hour, cost $100.
  • B: 10 jobs take 5 hours, cost 5 × $15 = $75.
  • A finishes 4 hours sooner, worth 4 × $6 = $24. So A's effective cost is $100 − $24 = $76 against B's $75.

It is almost a tie, with B just $1 cheaper. A is better if finishing early matters more than the saving. The point is that price per hour alone is the wrong measure: you must compare price per job including time saved (the price/performance idea).

How the idea grew

  1. 1960sJohn McCarthy: computation may someday be organised as a public utility.
  2. 1966Douglas Parkhill, "The Challenge of the Computer Utility": elastic, online, public/private/community forms.
  3. 1990sTelecoms switch from dedicated circuits to VPNs and balance traffic. The cloud symbol marks the provider/user boundary.
  4. 2006Amazon sells spare data-centre capacity (often only ~10% used) as Amazon Web Services.
  5. 2007–08Google, IBM and universities start research. Gartner sees a shift from owned assets to per-use services.

The five characteristics, and what they mean

  • On-demand self-service
  • Broad network access
  • Resource pooling (multi-tenancy)
  • Rapid elasticity
  • Measured service (metering)

Enabling technologies behind them: grid computing, cluster computing, utility computing, virtualization and service-oriented architecture.

Service models: who manages what

SaaS
Application-as-a-serviceYou just use the finished application. Examples: Google web apps, CRM such as Salesforce Sales Cloud and Service Cloud.
PaaSYou deploy your own code on the provider's platform. Examples: Google App Engine, Microsoft Azure.
IaaSYou rent virtual infrastructure (servers, storage, network) and manage everything above it. Example: Amazon EC2.

Memory hook: the higher up you go, the less you manage and the more the provider does.

Deployment models

Public cloud

Run by a cloud provider and offered to the general public.

Private cloud

For one organisation, either on-premise or externally hosted.

Community cloud

Shared by organisations with a common vision.

Hybrid cloud

A combination of any two or more of the models above.

Cloud layers (infrastructure)

  • Physical infrastructure
  • Virtual infrastructure
  • Applications and platform software
  • Cloud management and service-creation tools

Money: CapEx to OpEx

What you gain

No upfront hardware purchase (CapEx becomes OpEx), pay only for use, low barriers to entry, shared costs, low management overhead, terminate any time, SLAs with financial penalties.

What to watch

You may save little and even pay more in operating cost. It makes less sense when the capital expense is small or the capital budget is more flexible than the operating budget. Savings depend on your data-centre efficiency, existing costs, adoption level and what you host.

Billing items providers charge for: instances (extra for high-memory or high-CPU), data transfer in and out, storage (GB-month), I/O requests, PUT and GET requests, IP addresses, load balancing. Some let you bid on instances.

Internet-based computing where shared resources, software and information are provided on demand, like the electricity grid.

A metaphor from network diagrams, where a cloud shape stood for the abstracted network. It marked the boundary of provider responsibility.

Argues IT is becoming standardised and cheaper, like the move from private electricity generators to the grid.

1Explain why cloud computing arose and what "CapEx to OpEx" means.

Data centres were built for peak demand and sat mostly idle (Amazon's ran at about 10%). Amazon found that a new, shared architecture brought big efficiency gains and began selling access as AWS in 2006. Customers gain the same advantage: they rent computing instead of buying it, so a large one-time capital expenditure on hardware becomes a pay-as-you-go operating expenditure. That lowers barriers to entry, but the long-run operating bill can end up higher.

  • (b) IaaS, e.g. Amazon EC2.
  • (c) SaaS, e.g. Salesforce Sales Cloud.
  • (d) Hybrid cloud: a private cloud for the regulated data plus a public cloud for peak load.

Memory hierarchy: why caches work

L1 cache
smallest, fastest
L2 cache
L3 cache
Main memory
Secondary storage (swap space for virtual memory)
faster, smallerlarger, slower

Principle of locality: after touching one location you tend to touch a nearby one (spatial) or the same one again soon (temporal). Summing an array with a cache block of 16 reads 16 elements in one fetch, so 16 additions run before the next read. A hit is found in cache; a miss goes to a lower level. Write-through updates memory on every write; write-back marks the line dirty and writes it only when the line is replaced.

Virtual memory in four steps

  1. Too bigA program or its data may not fit in main memory.
  2. PagesKeep only active pages (4 to 16 KB) in memory; idle ones sit in swap space.
  3. Page tableMaps virtual page numbers to physical addresses, but adds time to every access.
  4. TLBA small cache (16 to 512 entries) of page-table entries. A page fault means the page is only on disk.

Inside one core: instruction-level parallelism

Not pipelined7000 ns
7-stage pipeline1006 ns

One addition still takes 7 ns, but once the pipeline is full a result finishes every ns, so 1000 additions take about 1006 ns (7 to fill, then 999 more).

Pipelining

Split a unit into stages; the output of one is the input of the next.

Multiple issue

Replicate functional units. Static: scheduled at compile time. Dynamic (superscalar): scheduled at run time.

Speculation

Guess an instruction's result (e.g. that z > 0), run ahead, and recompute if the guess was wrong.

Hardware multithreading

Fine-grained: switch every instruction, skipping stalled threads. Coarse-grained: switch only on long stalls. SMT: threads share the functional units at once.

Bank analogy: tellers are processors, customers are tasks. SIMD/SPMD: accounts are split among tellers who all do the same thing in lockstep. MIMD: each teller processes a transaction her own way, and any shared data access is locked.

SIMD, vectors and GPUs

SIMD

Same instruction on many data items (data parallelism). With 4 ALUs and 15 items it takes 4 rounds (4+4+4+3). Drawbacks: ALUs must all do the same thing or idle, they need no instruction storage, and it suits big regular data problems only.

Vector processors

Vector registers, vectorised and pipelined units, interleaved memory banks, strided access, scatter/gather. Pros: fast, easy to use, vectorising compilers, high memory bandwidth. Cons: poor on irregular data, limited scalability.

GPUs

Graphics pipeline turns points, lines and triangles into pixels. Several stages are programmable shader functions, implicitly parallel. Current GPUs use SIMD parallelism, though they are not pure SIMD.

Shared memory and the cache coherence problem

Shared-memory systems (SMP) let every processor reach every memory location through an interconnect. A bus does not scale well beyond about 64 processors because of bus contention.

UMA

Uniform memory access: identical processors, equal access time to all memory. Typical SMP, also called CC-UMA.

NUMA

Non-uniform: often several SMPs linked; memory across the link is slower. With coherence maintained it is CC-NUMA.

  1. Core 1 reads x = 15213 from main memory into its private cache.
  2. Core 2 reads x too: both caches hold 15213.
  3. Core 1 writes x = 21660 (assume write-through, so memory also has 21660).
  4. Core 2 reads x again from its own cache and gets the stale 15213. That is the coherence problem.
  5. Fix: invalidation-based protocol with snooping. Core 1's write sends an invalidation over the inter-core bus, so Core 2's copy is marked INVALID and it must refetch.

Invalidate vs update: after several writes to one location, invalidation signals only once; update must broadcast every write with its new value. So invalidation usually produces less bus traffic and performs better. More refined protocols such as MSI and MESI (Modified, Exclusive, Shared, Invalid) add cache state bits. Private caches are closer and cause less contention; shared caches let threads share data and give one busy thread more space.

Distributed memory and interconnects

Cluster

A collection of whole computers joined by a network and used as one unified resource with a single system image. Cheap, scalable, "typical" environment. Beowulf is a do-it-yourself Linux cluster of up to hundreds of nodes.

Loosely coupled

Whole computers (often heterogeneous) over TCP/IP. Suited to distributed applications, not parallel ones, unless very coarse-grained or trivially parallel.

Taxonomy in one tree

Parallel computers split into SIMD (vector, GPU) and MIMD (pipeline-style systems, multiprocessors with shared memory such as SMP and multicore, and loosely coupled multicomputers with distributed memory such as clusters).

Terms to know

Multitasking
Illusion of running many programs on one processor: each process takes a time slice, then waits.
Thread
A unit of work inside a process. When one thread blocks, another can run. A master thread starts threads (forking) and waits for them (joining).
Cache
Memory reachable faster than main memory, usually on the CPU chip.
Spatial / temporal locality
Next access is near this one / this location is accessed again soon.
Write-through / write-back
Update memory on every write / mark the line dirty and write on replacement.
Virtual memory
Main memory acting as a cache for secondary storage, holding only active pages.
Page table / TLB / page fault
Maps virtual to physical addresses / small cache of page-table entries / page is valid but only on disk.
ILP
Instruction-level parallelism: several functional units execute instructions at once (pipelining, multiple issue).
Superscalar
Dynamic multiple issue: units scheduled at run time.
SMT
Simultaneous multithreading: a variation of fine-grained multithreading that lets several threads use the functional units together.
SIMD / SPMD
Same instruction on many data (data parallelism). SPMD is the more common form on general-purpose machines.
MIMD
Independent processors with their own control unit and ALU.
SMP
Symmetric multiprocessor: shared global memory, equal access for all processors.
UMA / NUMA
Equal memory access time / unequal; CC-NUMA when cache coherent.
Cache coherence
If one processor updates a shared location, all others see the update. Done in hardware.
Snooping
Caches watch the shared bus for writes by others and invalidate their stale copy.
Diameter / bisection width
Longest shortest path between two nodes / simultaneous communications across the halves.

1Why do private caches create a coherence problem, and why is invalidation usually preferred over update?

Each core caches its own copy of x. When one core writes a new value, other cores' copies (and possibly memory) are now stale, so another core can read an outdated value. The fix is a hardware coherence protocol. In the invalidation-with-snooping approach a write sends an invalidation across the inter-core bus, other copies are marked invalid, and they refetch when needed. After repeated writes to the same location, invalidation signals only the first time, whereas update must broadcast every write with its value, so invalidation generates less bus traffic.

2Classify each with Flynn's taxonomy: (a) a GPU running one shader over many pixels, (b) a quad-core CPU running four different programs, (c) an old single-core PC. Then compute: a 7-stage, 1 ns-per-stage pipelined adder does 1000 additions. How long, and how much faster than unpipelined?
  • (a) SIMD, (b) MIMD, (c) SISD.
  • Pipelined: 7 + 999 = 1006 ns. Unpipelined: 1000 × 7 = 7000 ns, so about 7× faster (6.96).

Mind map

Swipe sideways to see the whole map

Why the burden moves to software

Problems keep growing (climate modelling, protein folding, drug discovery, energy research, data analysis) and hardware and compilers cannot keep pace. In shared-memory programs you start one process and fork threads; in distributed-memory programs you start multiple processes. Running many copies of a serial program does not help: you want one program to run faster. Automatic translators exist but have had limited success and often produce very inefficient code, so sometimes the best parallel solution is a brand-new algorithm.

Better algorithm: summing across cores

Two ways to split the work

Data parallelism

Split the data; each core does similar operations on its part. Professor P's 300 scripts: three assistants grade 100 exams each.

Task parallelism

Split the tasks. The same three assistants each grade a different set of questions: Q1–5, Q6–10, Q11–15 on every exam.

Issues in designing parallel programs

  • Communication: cores send partial sums to one another
  • Load balancing: share work evenly
  • Synchronization: keep cores from racing too far ahead

Grain size is how many tasks one processor handles. Coarse-grained has a high computation-to-communication ratio; fine-grained balances load more easily.

Amdahl vs Gustafson in words

Amdahl's law

S = 1 / (α + (1−α)/P). The problem size is constant; speedup is bounded by the serial fraction α. Models control parallelism (fork-join).

Gustafson-Barsis's law

S = P + (1−P)α. Programmers scale the problem up to use extra processors, so the serial share shrinks. Models data parallelism (SIMD/SPMD).

They are two models with different meanings of "serial part", not a contradiction. Slide example, α = 0.67 on 10 processors: Amdahl 1.42, Gustafson 3.97.

Why real speedup falls short

Shapes of speedup

Trivially parallel (ray tracing): S = P. Divide and conquer (merge sort): S ≈ P / log₂P. Communication-bound (large matrices): S ≈ 1/C(P). Super-linear exceeds the 45° line, but is rare.

Sources of overhead

Interprocess interaction, synchronization, idling (load imbalance, serial parts), contention for shared resources, excess computation (work the serial version never does). Roughly: Tparallel = Tserial / p + Toverhead.

Taking timings: decide what you are measuring (whole run, one segment, CPU time or wall-clock time). Use MPI_Wtime in MPI and omp_get_wtime in OpenMP. Communication cost is measured by latency (time for a message to cross) and bandwidth (data per unit time).

Amdahl fixes the problem size and asks how much faster that same problem runs on P processors; the serial fraction caps the speedup at 1/α. 3In the tree-style global sum, why does the master do fewer receives than in the naive version, and how many with 8 cores?

In the naive version every other core sends to core 0, so core 0 does 7 receives and 7 additions. In the tree version cores add in pairs and half of them drop out each round, so core 0 only handles log₂8 = 3 receives and additions. The work is shared instead of piled on one core, and the gap grows with more cores (10 vs 999 for 1000 cores).

Mind map

Swipe sideways to see the whole map

The map of communication models

Message passing (MPI)

Each process has local memory; data moves only by messages. Best for clusters and parallel programs.

Request-reply, RPC, RMI, gRPC

A client asks a server to run something and waits for the result. Remote invocation.

Group communication, multicast

One message to every member of a group, without knowing who they are.

Publish-subscribe

Publishers post events; subscribers receive the ones they registered interest in.

Message queuing

Sender and receiver need not run at the same time; messages wait in a queue.

Shared memory

Processes communicate by reading and writing shared data.

MPI

A message-passing library specification, not a language or a product. The MPI Forum began in 1992 and finalised the draft in May 1994; it is the de facto standard. A communicator groups processes and defines the context; MPI_COMM_WORLD holds all of them. Each process in a communicator has a rank numbered from 0.

Six functions are enough to write a complete program (MPI has 129): MPI_INIT, MPI_FINALIZE, MPI_COMM_SIZE, MPI_COMM_RANK, MPI_SEND, MPI_RECV.

program main
  MPI_INIT ( )
  MPI_COMM_SIZE (MPI_COMM_WORLD, count)
  MPI_COMM_RANK (MPI_COMM_WORLD, myid)
  print ("I am", myid, "of", count)
  MPI_FINALIZE ( )
end

Point-to-point

Always exactly two processes. MPI_Send(buf, count, datatype, dest, tag, comm) and MPI_Recv(buf, count, datatype, source, tag, comm, status). Blocking calls return when finished; non-blocking return right away so the program can do other work. Modes: standard, buffered, synchronous, ready.

Collective

Barrier: everyone waits until all arrive (no data). Broadcast: one to many. Reduction: many to one with a computation. Also scatter (one to many) and gather (many to one).

Every MPI message is typed: the datatype (e.g. MPI_INT, MPI_DOUBLE) must be given in both send and receive. Other services: virtual topologies, derived datatypes, dynamic task creation, client/server, one-sided put/get, parallel I/O.

Request-reply and its failure issues

The base protocol under RPC and RMI. The client calls doOperation and waits; the server's getRequest receives it, runs the method, and sendReply returns the result. Runs over UDP or TCP.

StyleClient sendsServer sends
RRequestnothing
RRRequestReply
RRARequest, then acknowledge the replyReply

Problems to handle: omission failures (lost messages), no guaranteed ordering, timeouts, discarding duplicate requests, lost replies, and keeping a history of replies.

RPC: ten steps

  1. Client procedure calls the client stub as if it were local.
  2. Stub marshals the procedure id and arguments into a message and calls the local OS.
  3. Client OS sends the message to the remote OS.
  4. Remote OS hands it to the server stub.
  5. Server stub unpacks (unmarshals) parameters and calls the server procedure.
  6. Server does the work and returns the result to the stub.
  7. Stub packs the result into a message and calls the OS.
  8. Server OS sends it to the client OS.
  9. Client OS gives the message to the client stub.
  10. Stub unpacks the result and returns to the client.

A dispatcher on the server picks which server stub handles a request. Synchronous RPC: the client blocks until the reply arrives. Asynchronous RPC: the client carries on after the request and the reply is handled later (it can even use two asynchronous calls, one each way).

RMI, DCE, gRPC

RMI

Invokes methods on objects in other processes. Uses a communication module (request-reply), a remote reference module (translates local and remote references), proxies on the client (hide marshalling) and a dispatcher plus skeleton on the server.

gRPC

Google's RPC stack, open-sourced in 2015. Uses protocol buffers (binary serialisation, open-sourced 2008: compact, fast, version-tolerant) over HTTP/2. Platform independent and high performance.

RPC vs RMISameDifferent
SimilaritiesProgramming with interfaces; built on request-reply; similar transparency; local and remote calls use the same syntax
DifferencesRMI is object-oriented, with unique object references and richer parameter passing; RMI invokes methods, RPC invokes functions

Group communication, overlays, pub-sub, queues

Multicast

One message to every member of a group. Benefits: fault tolerance through replicated services, service discovery, better performance via replicated data, event notification. Broadcast goes to all machines.

Group communication

The sender may not know the receivers. Groups are dynamic (create, join, leave). Needs FIFO, causal or total ordering, membership management, failure detection.

Overlay networks

Virtual nodes and links on top of an existing network, adding services (multicast, secure communication) without changing the underlying network. Examples: Skype, peer-to-peer sharing, streaming, multi-player gaming.

Publish-subscribe

Also "distributed event-based systems". Publishers publish structured events to an event service; subscribers register interest via subscriptions.

Queue primitiveMeaning

PollCheck the queue and remove the first message; never block
NotifyInstall a handler called when a message is put in the queue

Topologies: client-server (the most common), peer-to-peer (peers equally privileged, e.g. Napster, Kazaa, BitTorrent), and group (multicasting).

Exam traps

  • Amdahl keeps the problem size fixed; Gustafson grows it with P. Both are correct for their own model.
  • Parallel aims for faster execution (fine grain, tightly coupled); distributed aims at sharing resources (coarse grain, loosely coupled, no shared memory).
  • Strong scalability = fixed input; weak scalability = input grows with the processors.
  • Speedup is T(1)/T(p) against the best sequential program. Efficiency is speedup divided by p, not by time.
  • UMA: equal access time. NUMA: unequal. Both can be cache coherent (CC-UMA, CC-NUMA).
  • Invalidate beats update because it generates less bus traffic.
  • Write-through updates memory immediately; write-back marks lines dirty and writes later.
  • Page table maps virtual to physical addresses; the TLB caches page-table entries.
  • MISD is not commercially available; SIMD includes GPUs, MIMD includes multi-core.
  • RPC invokes functions; RMI invokes methods on objects. gRPC = protobuf + HTTP/2.
  • The cloud service models (IaaS, PaaS, SaaS) are different from the deployment models (public, private, community, hybrid).
  • Cloud can cost more in operating expense; CapEx savings are not guaranteed.
